WelcomeChào mừng

Thanks for helping! ccmon is MIT-licensed: you may use, modify, redistribute and sell it. To keep one shared source of truth, changes to the code go through the GitHub repository. Everyone taking part is expected to follow the Code of Conduct.

Found a bug or have an idea?

Open an issue. Search first, and include your OS, ccmon version and Claude Code version.

Want to change code?

Fork, branch, and open a pull request against main. For larger changes, open an issue first so we can agree on the approach.

Security problems are the exception: please do not open a public issue — follow the Security policy instead.

Cảm ơn bạn đã giúp! ccmon dùng giấy phép MIT: bạn được dùng, sửa, phân phối lại và bán. Để giữ một nguồn chung duy nhất, mọi thay đổi code đi qua repo trên GitHub. Mọi người tham gia cần tuân theo Quy tắc ứng xử.

Gặp lỗi hay có ý tưởng?

Mở một issue. Tìm trước, và ghi kèm hệ điều hành, phiên bản ccmon và phiên bản Claude Code.

Muốn sửa code?

Fork, tạo nhánh, rồi mở pull request vào main. Với thay đổi lớn, hãy mở issue trước để thống nhất cách làm.

Riêng lỗ hổng bảo mật: vui lòng không mở issue công khai — hãy làm theo Chính sách bảo mật.

PrerequisitesYêu cầu

  • Rust stable (CI uses dtolnay/rust-toolchain@stable).
  • Node.js 20+ and Yarn 1.x for the frontend.
  • The Tauri prerequisites for your OS. On Ubuntu:
  • Rust stable (CI dùng dtolnay/rust-toolchain@stable).
  • Node.js 20+ và Yarn 1.x cho frontend.
  • Các yêu cầu của Tauri cho hệ điều hành của bạn. Trên Ubuntu:
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev patchelf

Python 3 is only needed for the demo data generator. Without sudo, gui/build.sh can take WebKitGTK/GTK headers from extracted -dev packages in ~/.local/sysroot (or $CCMON_SYSROOT).

Python 3 chỉ cần cho bộ sinh dữ liệu demo. Không có sudo, gui/build.sh có thể lấy header WebKitGTK/GTK từ các gói -dev đã giải nén trong ~/.local/sysroot (hoặc $CCMON_SYSROOT).

Build, run & testBuild, chạy & kiểm thử

git clone https://github.com/<you>/cc-monitor && cd cc-monitor
cargo test --workspace              # core + GUI backend tests
./gui/build.sh                      # yarn install + build the frontend, then target/release/ccmon-gui
cargo run --release -p cc-monitor   # terminal UI
(cd gui/ui && yarn typecheck)       # TypeScript check (also part of `yarn build`)

The desktop binary embeds the built frontend from gui/ui/dist, so after changing anything in gui/ui/src rebuild with ./gui/build.sh (or cd gui/ui && yarn build followed by cargo build --release -p ccmon-gui). Installers are produced by the Tauri CLI in the release workflow; you don't need them for development.

What CI checksCI kiểm tra gì

.github/workflows/ci.yml runs on every push to main and every pull request, on ubuntu-22.04 and windows-latest:

  1. Test — yarn install --frozen-lockfile && yarn build in gui/ui (TypeScript check + Vite build), then cargo test --workspace.
  2. Smoke test — release build of ccmon-gui and ccmon, a ccmon tee round trip, then the desktop app is started on demo data and a screenshot is checked to be non-blank.

CI does not run cargo fmt --check or cargo clippy; formatting is part of the PR checklist instead. If you change gui/ui/package.json, commit the updated yarn.lock — CI installs with --frozen-lockfile.

.github/workflows/ci.yml chạy ở mỗi lần push vào main và mỗi pull request, trên ubuntu-22.04 và windows-latest:

  1. Test — yarn install --frozen-lockfile && yarn build trong gui/ui (kiểm tra TypeScript + build Vite), rồi cargo test --workspace.
  2. Smoke test — build release ccmon-gui và ccmon, thử một vòng ccmon tee, rồi mở ứng dụng desktop trên dữ liệu demo và kiểm tra ảnh chụp màn hình không trắng trơn.

CI không chạy cargo fmt --check hay cargo clippy; định dạng code nằm trong checklist PR. Nếu sửa gui/ui/package.json, hãy commit cả yarn.lock đã cập nhật — CI cài với --frozen-lockfile.

Architecture overviewTổng quan kiến trúc

Claude Code ──writes──► ~/.claude/projects/…/<session>.jsonl            ccmon (read-only)
             (+ sub-agent & workflow transcripts, file backups) ─► tail every 200 ms ─► thread tree ─► UI
                                                                   parse tolerantly

A background worker (discovery.rs) finds sessions and tails new lines (tail.rs, about 0.4 s end to end). event.rs turns each JSONL line into an event; thread.rs and store.rs rebuild the live branch of each thread (rewinds and /compact included). The code is organised in three layers:

  • Observe — parse and store; never writes. Unknown lines become a generic event, parsing never panics. Background tasks are tracked in bgtask.rs.
  • Catalog (src/catalog/) — “what exists” (providers scanning disk, one per kind: skill, plugin, MCP, agent, workflow) and “what was available / used” in a session (usage.rs), plus run history.
  • Control (src/control/) — “what may the next turn use”: a per-session Overlay is translated into claude CLI flags (--model, --effort, --permission-mode, --agent, --disallowedTools, --settings) and a long-lived claude -p child is managed by runner.rs. It only writes ccmon-owned state.

The Tauri backend exposes these as commands (gui/src-tauri/src/*.rs, registered in main.rs); their DTOs are mirrored in gui/ui/src/api.ts. Read the full notes in the repository:

  • capabilities.md — the three layers, the provider contract, state conventions and a step-by-step checklist for adding a new capability kind.
  • control.md — the verified mapping from overlay fields to Claude Code CLI flags, binary lookup and limitations.

Một worker chạy nền (discovery.rs) tìm session và đọc dòng mới (tail.rs, trễ khoảng 0,4 giây). event.rs biến mỗi dòng JSONL thành một sự kiện; thread.rs và store.rs dựng lại nhánh đang sống của từng luồng (kể cả rewind và /compact). Code chia thành ba lớp:

  • Observe — parse và lưu; không bao giờ ghi. Dòng lạ thành sự kiện chung, parse không bao giờ panic. Tác vụ nền được theo dõi trong bgtask.rs.
  • Catalog (src/catalog/) — “có những gì” (provider quét đĩa, mỗi loại một provider: skill, plugin, MCP, agent, workflow) và “session đã được cung cấp / đã dùng gì” (usage.rs), cùng lịch sử chạy.
  • Control (src/control/) — “lượt sau được dùng gì”: Overlay theo session được dịch thành cờ CLI của claude (--model, --effort, --permission-mode, --agent, --disallowedTools, --settings) và một tiến trình con claude -p sống lâu do runner.rs quản lý. Lớp này chỉ ghi trạng thái của chính ccmon.

Backend Tauri đưa các lớp này ra thành command (gui/src-tauri/src/*.rs, đăng ký trong main.rs); DTO tương ứng nằm trong gui/ui/src/api.ts. Ghi chú đầy đủ trong repo (tiếng Anh):

  • capabilities.md — ba lớp, hợp đồng provider, quy ước trạng thái và checklist từng bước để thêm một loại capability mới.
  • control.md — ánh xạ đã kiểm chứng từ overlay sang cờ CLI của Claude Code, cách tìm binary và các giới hạn.

Principles & conventionsNguyên tắc & quy ước

Principles

  • Read-only. ccmon never writes into ~/.claude, except the explicit, opt-in status-line wrapper (with backup and an uninstall button) and agent files the user saves from the Agents page after confirming.
  • Local only. No network calls, no telemetry.
  • Tolerant parsing. The transcript format is internal to Claude Code and changes; unknown lines must be skipped, never crash the app.

Conventions in the code

  • Format Rust with cargo fmt --all.
  • New parsing behaviour gets a test with a small, hand-written fixture. Never paste real transcripts.
  • Catalog providers follow the contract in capabilities.md: stable ids (never derived from a path or index), no IO outside ScanCtx, no network, never panic — missing or malformed files yield fewer items, not errors.
  • ccmon state is written atomically (temp file + rename); reads fall back to defaults on missing or corrupt files; any path built from a session id is validated first.
  • Code must work on both Linux and Windows (CI tests both): use the helpers in src/platform.rs for paths, shells and processes.
  • UI strings are currently Vietnamese; an English UI is planned, and help with it is welcome.

Nguyên tắc

  • Chỉ đọc. ccmon không bao giờ ghi vào ~/.claude, trừ lớp bọc status line do người dùng chủ động chọn (có sao lưu và nút gỡ) và file agent người dùng lưu từ trang Agents sau khi xác nhận.
  • Chỉ cục bộ. Không gọi mạng, không telemetry.
  • Parse khoan dung. Định dạng transcript là nội bộ của Claude Code và thay đổi; dòng lạ phải được bỏ qua, không bao giờ làm sập ứng dụng.

Quy ước trong code

  • Định dạng Rust bằng cargo fmt --all.
  • Hành vi parse mới phải có test với fixture nhỏ, viết tay. Không bao giờ dán transcript thật.
  • Provider của catalog tuân theo hợp đồng trong capabilities.md: id ổn định (không suy ra từ đường dẫn hay chỉ số), không IO ngoài ScanCtx, không gọi mạng, không panic — file thiếu hoặc hỏng chỉ cho ít mục hơn, không báo lỗi.
  • Trạng thái của ccmon được ghi nguyên tử (file tạm + rename); khi đọc, file thiếu hoặc hỏng thì dùng mặc định; mọi đường dẫn tạo từ session id đều được kiểm tra trước.
  • Code phải chạy được trên cả Linux và Windows (CI kiểm tra cả hai): dùng các hàm trong src/platform.rs cho đường dẫn, shell và tiến trình.
  • Chuỗi giao diện hiện là tiếng Việt; giao diện tiếng Anh đang được lên kế hoạch, rất hoan nghênh giúp đỡ.

Commits & pull requestsCommit & pull request

  1. Fork the repository and create a branch from main (e.g. fix/windows-paths, feat/…).
  2. Keep each PR focused on one change. For anything large, agree on the approach in an issue first.
  3. Commit messages follow the style already in the history — a Conventional Commits-like prefix with an optional scope, e.g. feat(gui): highlighted @agent mentions, fix(catalog): …, docs: …, style: cargo fmt.
  4. Open the pull request against main and fill in the template: What & why and How I tested.

Pull request checklist

  • cargo test --workspace passes, and cd gui/ui && yarn typecheck passes
  • cargo fmt --all applied
  • New parsing behaviour has a test with a small fixture (never real transcripts: they contain private code and prompts)
  • UI changes include a screenshot in the PR description

CI runs on every pull request; please make sure it passes before asking for review. The project is MIT-licensed, and contributions are expected to be submitted under the same license.

  1. Fork repo và tạo nhánh từ main (ví dụ fix/windows-paths, feat/…).
  2. Mỗi PR chỉ tập trung một thay đổi. Việc lớn thì thống nhất cách làm trong issue trước.
  3. Commit message theo phong cách sẵn có trong lịch sử — tiền tố kiểu Conventional Commits kèm phạm vi tuỳ chọn, ví dụ feat(gui): highlighted @agent mentions, fix(catalog): …, docs: …, style: cargo fmt.
  4. Mở pull request vào main và điền mẫu: What & why và How I tested.

Checklist cho pull request

  • cargo test --workspace qua, và cd gui/ui && yarn typecheck qua
  • Đã chạy cargo fmt --all
  • Hành vi parse mới có test với fixture nhỏ (không dùng transcript thật: chúng chứa code và prompt riêng tư)
  • Thay đổi giao diện có ảnh chụp trong mô tả PR

CI chạy trên mọi pull request; hãy bảo đảm nó qua trước khi nhờ review. Dự án dùng giấy phép MIT, và phần đóng góp được hiểu là gửi theo cùng giấy phép đó.

Reporting bugs & requesting featuresBáo lỗi & đề xuất tính năng

Use the issue forms. Search existing issues first.

  • Bug report — ccmon version and operating system (required), Claude Code version (claude --version), what happened and what you expected (steps to reproduce help a lot), screenshots or logs.
  • Feature request — the problem it would solve (required) and your idea.

Remove private code and prompts from screenshots and logs before posting. Do not attach real transcripts.

Dùng mẫu issue. Hãy tìm trong các issue có sẵn trước.

  • Bug report — phiên bản ccmon và hệ điều hành (bắt buộc), phiên bản Claude Code (claude --version), chuyện gì xảy ra và bạn mong đợi gì (các bước tái hiện giúp rất nhiều), ảnh chụp hoặc log.
  • Feature request — vấn đề cần giải quyết (bắt buộc) và ý tưởng của bạn.

Xoá code và prompt riêng tư khỏi ảnh chụp và log trước khi đăng. Không đính kèm transcript thật.

Release processQuy trình phát hành

Releases are automated by .github/workflows/release.yml:

  1. Bump the version in a PR. The workflow reads version from the root Cargo.toml; keep gui/src-tauri/Cargo.toml and gui/src-tauri/tauri.conf.json (which names the installer files) at the same version.
  2. Merge to main. If no tag v<version> exists yet, the workflow tags HEAD and creates a draft GitHub Release; otherwise nothing happens.
  3. On ubuntu-22.04 and windows-latest, tauri-action builds the installers (.exe NSIS, .msi, .AppImage, .deb) and uploads them, and the TUI is attached as ccmon-cli-linux-x64 / ccmon-cli-windows-x64.exe.
  4. A maintainer reviews the draft and publishes it; the website's download buttons pick up the latest published release.

A release can also be started by pushing a v* tag by hand, or re-built from the Actions tab (“Run workflow” with an existing tag).

Website

The site in website/ is deployed by .github/workflows/pages.yml on every push to main that touches website/**. It is plain HTML/CSS/JS: open the files directly or serve the folder (python3 -m http.server -d website) to preview.

Việc phát hành được tự động hoá bằng .github/workflows/release.yml:

  1. Tăng phiên bản trong một PR. Workflow đọc version trong Cargo.toml gốc; hãy giữ gui/src-tauri/Cargo.toml và gui/src-tauri/tauri.conf.json (quyết định tên file bộ cài) cùng phiên bản.
  2. Merge vào main. Nếu chưa có tag v<version>, workflow gắn tag cho HEAD và tạo một GitHub Release dạng nháp; nếu đã có thì không làm gì.
  3. Trên ubuntu-22.04 và windows-latest, tauri-action build bộ cài (.exe NSIS, .msi, .AppImage, .deb) và tải lên, còn TUI được đính kèm dưới tên ccmon-cli-linux-x64 / ccmon-cli-windows-x64.exe.
  4. Maintainer kiểm tra bản nháp rồi công bố; nút tải trên website lấy bản phát hành công bố mới nhất.

Cũng có thể phát hành bằng cách tự push tag v*, hoặc build lại từ tab Actions (“Run workflow” với một tag có sẵn).

Website

Website trong website/ được .github/workflows/pages.yml triển khai ở mỗi lần push vào main có đụng tới website/**. Đây là HTML/CSS/JS thuần: mở file trực tiếp hoặc phục vụ thư mục (python3 -m http.server -d website) để xem trước.
