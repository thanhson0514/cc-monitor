Supported versionsPhiên bản được hỗ trợ

ccmon is a young project maintained by volunteers. Security fixes are made on main and shipped in the next release; older releases are not patched. Please update to the latest release before reporting.

ccmon là dự án còn non trẻ do tình nguyện viên duy trì. Bản vá bảo mật được làm trên main và phát hành ở bản kế tiếp; các bản cũ không được vá. Vui lòng cập nhật lên bản mới nhất trước khi báo cáo.

Reporting a vulnerabilityBáo cáo lỗ hổng

Please do not report security vulnerabilities through public GitHub issues, pull requests or discussions.

Report privately through GitHub's private vulnerability reporting:

Report a vulnerability

or open the repository's Security tab and choose Report a vulnerability. Only the maintainers can see the report. Please include as much as you can:

  • ccmon version, operating system, and whether it is the desktop app or the terminal UI;
  • the type of issue (for example path traversal, command injection, script injection in the webview, unintended file writes);
  • step-by-step instructions to reproduce, with a proof of concept if possible;
  • the impact: what an attacker could do, and what they need first.

Use a minimal, synthetic transcript to demonstrate the problem — never send real transcripts, which contain private code and prompts.

Vui lòng không báo cáo lỗ hổng bảo mật qua issue, pull request hay thảo luận công khai trên GitHub.

Hãy báo cáo riêng tư qua tính năng private vulnerability reporting của GitHub:

Báo cáo lỗ hổng

hoặc mở tab Security của repo và chọn Report a vulnerability. Chỉ maintainer thấy được báo cáo. Hãy ghi càng đầy đủ càng tốt:

  • phiên bản ccmon, hệ điều hành, và đó là ứng dụng desktop hay giao diện terminal;
  • loại vấn đề (ví dụ path traversal, chèn lệnh, chèn script vào webview, ghi file ngoài ý muốn);
  • các bước tái hiện, kèm proof of concept nếu có;
  • mức ảnh hưởng: kẻ tấn công làm được gì, và cần gì trước đó.

Dùng một transcript tổng hợp, tối thiểu để minh hoạ — không bao giờ gửi transcript thật, vì chúng chứa code và prompt riêng tư.

What happens nextĐiều gì xảy ra tiếp theo

  1. We acknowledge the report in the private advisory as soon as we can and confirm whether we can reproduce it.
  2. We work on a fix in the advisory's private fork and keep you updated there. You are welcome to review the fix.
  3. We release a fixed version, publish the advisory (requesting a CVE where appropriate) and credit you, unless you prefer to stay anonymous.

We follow coordinated disclosure: please give us reasonable time to ship a fix before you publish details. Reports made in good faith that respect users' privacy and avoid harm are welcome — thank you for helping keep ccmon users safe.

  1. Chúng tôi xác nhận đã nhận báo cáo trong advisory riêng tư sớm nhất có thể và cho biết có tái hiện được không.
  2. Chúng tôi sửa lỗi trong fork riêng tư của advisory và cập nhật cho bạn ở đó. Bạn được mời review bản sửa.
  3. Chúng tôi phát hành phiên bản đã sửa, công bố advisory (xin mã CVE khi phù hợp) và ghi công bạn, trừ khi bạn muốn ẩn danh.

Chúng tôi theo nguyên tắc công bố phối hợp: vui lòng cho chúng tôi thời gian hợp lý để phát hành bản sửa trước khi công bố chi tiết. Mọi báo cáo thiện chí, tôn trọng quyền riêng tư của người dùng và tránh gây hại đều được hoan nghênh — cảm ơn bạn đã giúp người dùng ccmon an toàn hơn.

ScopePhạm vi

In scope

  • The ccmon desktop app (ccmon-gui), the terminal UI (ccmon) and the installers attached to GitHub Releases.
  • Especially: untrusted transcript content (Markdown, tool output, file names) reaching the webview or the Tauri commands; files written outside ccmon's state folder or the documented locations; the tee status-line wrapper; the arguments ccmon passes when it launches claude; secrets from MCP or settings files being exposed in the UI.
  • This website, cc-monitor.online.

Out of scope

  • Vulnerabilities in Claude Code itself — please report those to Anthropic through its own disclosure process.
  • Vulnerabilities in Tauri, WebView2, WebKitGTK or other dependencies, unless ccmon uses them in an unsafe way — please report upstream (and let us know if a ccmon update is needed).
  • Behaviour that works as documented, for example the bypassPermissions mode letting an agent run any tool, or a terminal session staying view-only.
  • Attacks that require an attacker who can already write to your home directory or run code as your user.

Trong phạm vi

  • Ứng dụng desktop ccmon (ccmon-gui), giao diện terminal (ccmon) và các bộ cài đính kèm trên GitHub Releases.
  • Đặc biệt: nội dung transcript không tin cậy (Markdown, output của tool, tên file) tác động tới webview hoặc các command của Tauri; file bị ghi ra ngoài thư mục trạng thái của ccmon hoặc các vị trí đã nêu; lớp bọc status line tee; tham số ccmon truyền khi khởi chạy claude; bí mật trong file MCP hay settings bị lộ lên giao diện.
  • Website này, cc-monitor.online.

Ngoài phạm vi

  • Lỗ hổng của chính Claude Code — vui lòng báo cho Anthropic theo quy trình công bố của họ.
  • Lỗ hổng của Tauri, WebView2, WebKitGTK hay phụ thuộc khác, trừ khi ccmon dùng chúng thiếu an toàn — vui lòng báo cho dự án gốc (và cho chúng tôi biết nếu ccmon cần cập nhật).
  • Hành vi đúng như tài liệu, ví dụ chế độ bypassPermissions cho agent chạy mọi tool, hay session ở terminal chỉ được xem.
  • Tấn công đòi hỏi kẻ tấn công đã ghi được vào thư mục home của bạn hoặc chạy code dưới tài khoản của bạn.

Security model, in shortMô hình bảo mật, tóm tắt

  • ccmon is a local app that runs with your user's permissions and opens no network connections (see Privacy).
  • Watching is read-only. Writes are limited to ccmon's own state folder, plus the opt-in status-line wrapper (with a backup) and agent files you confirm.
  • State files are written atomically, and any path built from a session id is validated first.
  • MCP server environment variables and headers are not shown; credentials and query strings are stripped from MCP URLs before display.
  • Sessions run from ccmon are ordinary claude -p processes with the permission mode you choose. Tools that need approval are denied unless you pick a more permissive mode.
  • ccmon là ứng dụng cục bộ chạy với quyền của tài khoản bạn và không mở kết nối mạng (xem Quyền riêng tư).
  • Theo dõi thì chỉ đọc. Việc ghi giới hạn trong thư mục trạng thái của ccmon, cùng lớp bọc status line do bạn chọn (có sao lưu) và file agent bạn xác nhận.
  • File trạng thái được ghi nguyên tử, và mọi đường dẫn tạo từ session id đều được kiểm tra trước.
  • Biến môi trường và header của MCP server không được hiển thị; thông tin đăng nhập và query string bị cắt khỏi URL MCP trước khi hiển thị.
  • Session chạy từ ccmon là tiến trình claude -p bình thường với chế độ quyền bạn chọn. Tool cần duyệt sẽ bị từ chối trừ khi bạn chọn chế độ thoáng hơn.
