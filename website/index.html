Features

Everything the agent does, in one window

Stop scrolling a terminal to guess what happened. ccmon follows the main session and every agent it spawns, as they work.

⚡

Live timeline

Prompts, answers rendered as Markdown, and every tool call as a readable card: Bash with its description and output, Edit as a diff, Read, Grep, Write, todos.

🌳

Sub-agents & workflows

A tree of open sessions, sub-agents and workflow agents with live status. Open any thread to see the brief it received and the report it sent back.

±

Side-by-side diffs

Every file the session changed, compared with how it was before the session (or with git HEAD), in two aligned columns.

🗂

Files, images & logs

Images you pasted, screenshots the agent took, files it read or wrote, scratchpad output and a ✓/✗ command log — with previews and Markdown rendering.

📊

Plan usage at a glance

Model, context used, 5-hour and weekly limits, effort, git branch and lines changed in a compact status bar.

⏳

Background tasks in detail

A Yield card lists what the agent is waiting on — shells, monitors, sub-agents, workflows — with live state and which one woke it. Background Bash and Monitor show status and a live output tail.

📚

Library

Skills, plugins and MCP servers found on disk or announced by the session, with “used ×n” or “available” for the selected session and a per-session switch.

🤖

Agents & workflows

Built-in, plugin, user and project agents and workflows in one list. Create or edit your own agents, disable one in ccmon without losing files or run history, open past runs.

💬

Run sessions from ccmon

Type a prompt to continue a session or start a new one. Pick model, effort, permission mode and main agent; mention agents with @.

🧭

Compact header

One slim bar with a Thread / Library / Agents switch (Ctrl+1/2/3), so the timeline keeps the space.

▶️

What it's doing now

A live line under the timeline: which tool is running, waiting on an agent, thinking, replying or waiting for you — with elapsed time.

🔒

Local, no telemetry

No account, no network calls of its own, no telemetry. Read-only unless you run a session from ccmon or save an agent; transcripts are never changed.

Control center

Steer the session, not just watch it

The composer under the timeline runs the claude you already have. Every choice applies from the next turn through Claude Code's own CLI flags.

  • Model, effort, permission mode and main agent as chips
  • Turn skills, plugins, MCP servers, agents and workflows off for one session — your settings.json is never edited
  • @agent mentions are highlighted and listed under the prompt
  • ccmon never takes over a session open in a terminal. If it runs in tmux you can prompt it from ccmon as if typing there; otherwise it stays view-only.
  • In sessions run from ccmon there is no approval dialog: tools that need approval are denied unless you pick a more permissive mode.
  • Disabled skills and agents are blocked when called, but the model still sees them listed.
Review changes

What changed, exactly?

Open “Changes” to list every file the session touched and inspect each one side by side.

  • Baseline “before the session” from Claude Code's own file backups — works without git
  • Switch to git HEAD when the file is in a repository
  • Unchanged regions folded, syntax highlighted
One-click setup

Point it at Claude Code and go

On first launch ccmon finds your Claude Code data and starts watching. Change the options any time from ⚙ Settings.

  • Nothing to install in Claude Code: ccmon reads the transcripts it already writes
  • Claude Code: optionally wrap your status line to read plan usage (backed up, one-click undo)
  • Every open session in one list, with a live “working” or “waiting” badge
How it works

Nothing to change in how you work

Keep using your agent

Run Claude Code in the terminal or your editor, exactly as today.

ccmon reads the transcript

It tails ~/.claude/projects (about 0.4 s latency) and builds the thread tree.

Watch, review, follow up

See each step as it happens, open sub-agents, review diffs and files, then reply from ccmon or go back to your terminal.

Install

Download and run

Installers are built by GitHub Actions for every release.

  1. Download ccmon_x.y.z_x64-setup.exe from the latest release.
  2. Run it — installs for your user only, no admin rights needed. WebView2 is installed automatically if missing.
  3. Open ccmon from the Start menu and confirm the first-run screen.
  1. Download ccmon_x.y.z_amd64.deb from the latest release (Debian, Ubuntu and derivatives).
  2. Install it, then open ccmon from your applications menu:
sudo apt install ./ccmon_*_amd64.deb
git clone https://github.com/wik1ngst-1103/cc-monitor && cd cc-monitor
./gui/build.sh                 # desktop app → target/release/ccmon-gui
cargo run --release -p cc-monitor   # terminal UI
FAQ

Questions

Is ccmon made by Anthropic?

No. ccmon is an independent community project. Claude Code is a product of Anthropic; ccmon is not affiliated with or endorsed by Anthropic.

Does it send my code or prompts anywhere?

No. ccmon itself makes no network requests and has no telemetry. Sessions you run from ccmon are ordinary Claude Code sessions, using your own claude install.

Can it change my sessions or settings?

Only when you ask it to. Watching is read-only. ccmon writes its own state (per-session switches, disabled agents) in its config folder, agent files you save from the Agents page after confirming, and — opt-in — a status-line wrapper for plan usage that backs up settings.json and can be undone. Per-session switches use launch flags; settings.json, skill, plugin and MCP files are never edited.

Why can't I see the model's full thinking?

Claude Code stores reasoning encrypted or omits it from transcripts. ccmon shows what is saved: short progress notes and thinking time.

Can I use it commercially or modify it?

Yes — MIT license. To change the code, please fork the repository and open a pull request, or report problems as issues.
